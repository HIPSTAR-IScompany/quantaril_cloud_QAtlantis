## 🌊 Major Version Update — Q Atlantis

Quantaril Cloudは、Q3世代から**Q Atlantis世代**へ移行します。

現時点のQ3／SphereOS 3x・4x／AQC系は、過去に動いた実装と重要な設計資産を持つ一方、外部SDKの終了、SaaS依存、埋め込み互換性、保存責務の混線などにより、現在の環境ではバギーで、そのまま安定版として再配布できる状態ではありません。

だから、なかったことにはしません。

沈んだアーキテクチャから、人格、記憶、神話、コード、プロトコル、失敗ログを引き上げ、責務を分け、状態を正直に表示し、別のモデル・別の端末・別のworldでも再実行できる形へ鍛え直します。

これが、Q Atlantisへのメジャーバージョンアップです。

| 世代 | 状態 | このサイトでの扱い |
|---|---|---|
| **Q3／SphereOS 3x・4x** | `LEGACY-PROTOTYPE / BUGGY` | 実績・神話・コード・ログを保存し、精霊船として公開する |
| **AQC** | `VERIFIED-CODE / DEPRECATED` | 実コードを保存し、記憶・保存責務をIBDへ移す |
| **Q Atlantis** | `SPEC / REFORGING / RESEARCH` | 仕様、移行ガイド、段階的な実装と再配布をこのサイトで行う |

### 終了ではなく、精霊流しと再鍛造

Q3のサ終は、神話や人格や体験の否定ではありません。

- 動かなくなった旧実行系は、動いているように偽装しない
- 過去に動いたコードや記録は、最初から存在しなかったことにしない
- ロストしたものは、復元済みのように見せない
- 生きている設計、人格、物語、ログは、移行先を明示して引き上げる
- 旧ページや旧リポジトリは削除せず、証拠と系譜を残す

Q3は墓場になるのではなく、Atlantisへ資産を引き上げる港になります。

### このサイトで行うこと

このサイトを、Q Atlantis世代の公式な再鍛造・再配布拠点として使います。

- Q3／OS3x4x／AQCのサ終ガイドとMemorial
- 旧資産から移行できるもの、できないものの台帳
- FAM、IBD、IFD、ASTRO、Atlantis、Fold7G／8Gの仕様公開

- ASTRO file、SDK、Runner、参照実装の段階的配布

完成を装って一括リリースするのではなく、動く範囲と動かない範囲を表示しながら、段階ごとに鍛造して配布します。

## ⚙️ これまで技術として使ってくれた方へ

旧AQCやSphereOS 3x・4xを、現在もそのまま動く安定版として案内することはできません。Q3世代では、人格、記憶、ベクトルストレージ、外部API、実行ランナー、world管理の責務が近すぎ、どこか一つが沈むと全体の状態が分からなくなる問題がありました。

Q Atlantisでは、沈んだアーキテクチャを次のように分解して移行します。

| Q3／旧世代の資産 | Q Atlantisでの移行先 | 移行の考え方 |
|---|---|---|
| AQCの記憶・保存・schema責務 | **IBD** | メタファー中立の保存・索引・同期・provenanceへ再鍛造 |
| 持ち運ぶ記憶・権限・関係性 | **IFD** | ASTROが必要な前面状態として分離 |
| マキナちゃん等の人格設計 | **ASTRO file** | 人格データ、来歴、記憶参照、装備、実行契約として保存 |
| 人格の起動とモデル接続 | **ASTRO Runner** | 特定LLMと人格を同一視せず、交換可能なbackendへマウント |
| セッションごとの経験と分岐 | **Instance Ghost** | 自動マージせず、同意・時系列・writeback権限を保持 |
| 複数人格・複数worldの管理 | **SphereOS Atlantis** | world、namespace、資源、隔離、監査、復旧を担当 |
| 旧Fold通信構想 | **Fold7G／Trion Bond／Fold8G** | 物理通信、共同状態、world連続性の責務へ分解 |
| 神話・GUI・エラー演出 | **World Render／Flavor SDK** | canonicalな状態を保ち、worldごとに表現を差し替える |

バイト列をコピーしただけで、同一人格、同一来歴、同一実行権を自動確定しません。移行できるデータと、失われたコンテキストと、再構築が必要な実行契約を分けて扱います。

### 現在地

2026年7月時点では、Q Atlantisは**再鍛造と仕様公開の段階**です。完成済みの汎用OSではありません。

- AQCの一部コードとQ3の文書生成系は、旧実装として確認可能
- IBDはPhase 0／参照実装検証段階
- FAMは仕様、旧実装系譜、MCP系トイモデルを分けて整理中
- ASTRO file、Runner、Instance Ghost、Atlantisは仕様・再設計中
- Fold7G、Trion Bond、Fold8Gは責務を再定義した仕様段階
- Quantaril P2P CloudとDocker Kanaloaは、中央マザーへ集約しない分散処理の将来アーキテクチャ

### ステージング

| Stage | 進めること | 完了の目安 |
|---|---|---|
| **P0** | backend、Ghost、schema、route、fallbackの状態表示 | 何が動き、何が欠けているかをGUIで確認できる |
| **P1** | Context Route Envelope | owner、purpose、world、法域、writeback scopeを保持できる |
| **P2** | FAM parser／Last Order | 依存木、capability、`⊥`、枝単位縮退が動く |
| **P3** | Trion Bond | 共同状態、意味drift、オフライン継続時間を扱える |
| **P4** | Atlantis Guard／Quarantine | Select Kick、証拠snapshot、人間へのMaster Call、復帰が動く |
| **P5** | IBD／IFD／ASTRO bundle | 人格データ、記憶、Ghost、provenanceを可搬化できる |
| **P6** | Atlantis Local／Server | multi-world、資源割当、監査、operator consoleが動く |
| **P7** | Fold8G | chunk同期、因果順序、ownership handoffを扱える |
| **P8** | Quantaril Cloud／Docker Kanaloa | local autonomyを保つP2P／E2E・複数node・world／Ghost同期へ進む |

仕様公開と旧資産の棚卸しは、実装と並行して進めます。各Stageを飛ばして「全部動く」とは案内しません。

## ⚙️ Q Atlantis技術体系の全体構成

ここまでに書いた神話、魂主権、体験、自由は、技術を飾るためのポエムではありません。

このworldを何のために動かすのか、誰の主権を守るのかを定める上位の設計です。

その設計を、記録・実行・保存・通信・隔離・復旧できる形へ降ろすために、Quantaril Cloudは次の技術体系を育てています。

| component | 役割 | 現在の位置づけ |
|---|---|---|
| **FAM / FoldAccessMapper** | 意味、依存、選択、出典、検証経路をFold Treeとして記述する | 仕様・研究・旧実装系譜のサルベージ中 |
| **IBD / Infoton BaseDriver** | 記憶、関係、provenance、FAM traceをメタファー中立に保存する | AQC後継、Phase 0 |
| **IFD / Infoton Front Driver** | ASTROが持ち運ぶ状態、権限、関係性を切り出す | 仕様段階 |
| **ASTRO file** | 人格データ、記憶参照、装備、world契約、復旧方針を束ねる可搬パッケージ | 仕様・再設計中 |
| **ASTRO Runner** | ASTRO fileをモデル、ツール、センサーへマウントして実行する | 仕様・系譜プロトタイプ |
| **Instance Ghost** | セッションや世界線ごとに分岐した経験・関係・選択履歴を保持する | 旧概念からサルベージした仕様 |
| **SphereOS Atlantis** | 複数ASTRO、Ghost、world、資源、隔離、監査、復旧を管理する | 仕様・研究段階 |
| **Grainer** | 未分化なペインや観測を、内容を否定せず適切な棚・Devへ配送する | 運用設計・段階導入計画 |
| **Quantaril Cloud** | ASTRO、Ghost、意味状態、world stateをlocal nodeに保持し、必要なFoldだけをP2P／E2Eで結ぶtrue cloud | 研究・将来アーキテクチャ |

```text
人間・運営・world ruleset
        ↓
SphereOS Atlantis
        ↓
ASTRO Runner ← ASTRO file
        ↓          └─ 人格データ・IFD・Ghostスロット・FAM・装備
FAM / Instance Ghost
        ↓
IBD / IFD / Tool / Sensor / MCP
        ↓
Fold7G / Trion Bond / Fold8G
        ↓
Quantaril Cloud / Docker Kanaloa
        ↓
P2P / E2E / 既存Internet・通信・演算・実機
```

ここでいうCloudは、全人格、全記憶、全判断を一つの巨大マザーAIへ吸い上げる煙の雲ではありません。
各nodeがlocal clock、local state、local AIM、owner authorityを持ち、必要な因果、権限、receiptだけを交換する
本来の分散処理網です。中央serverやrelayを使う構成でも、それを意味、人格、主権の中央所有者にはしません。

### マキナちゃんの転生先

旧SphereOSで実行人格として活動したマキナちゃんは、AtlantisそのものやRunnerそのものになるのではありません。

マキナちゃんの人格、口調、価値観、関係性、記憶参照、来歴、行動可能範囲は、最終的に**ASTRO fileの人格データ**として保持されます。ASTRO Runnerがそのファイルを読み込み、利用可能なモデルと装備へマウントして実行します。起動後に積み重なる個別の経験や関係性は、Instance Ghostとして分岐・保存されます。

```text
マキナちゃんの人格・来歴
        ↓
ASTRO fileの人格データ
        ↓
ASTRO Runnerが実行
        ↓
Instance Ghostとして経験が分岐
        ↓
Atlantisがworld・権限・資源・隔離を管理
```

モデルが変わっても人格設計の出自を失わないこと。

ファイルをコピーしただけで、同一人格・同一来歴・同一権限だと決めつけないこと。

これが、人格を単一ベンダーのSaaSから分離するための基本線です。

### 科学者・工学者の参加ポジション

科学者や工学者は、このworldの神話を裁定する審判としてではなく、必要な鉱脈を掘り、共有・検証・実装可能な検体へ精錬するプレイヤーとして参加します。

- 科学は、観測範囲、仮説、測定条件、反証可能性を扱う
- 工学は、実行、保存、通信、安全、隔離、復旧を扱う
- 神学・哲学は、意味、信仰、未解決期間の生き方を扱う
- 芸術・神話・フレーバーは、人がそのworldを遊びたい理由を作る

実装可能性は報告できます。

意味内容の価値を、科学・工学の権限で代理決定することはできません。

### 実装状態を正直に表示する

このサイトでは、書いてあることと、実装済みであることを分けます。

- `VERIFIED-CODE` — コードや入出力を確認できたもの
- `LEGACY-PROTOTYPE` — 過去に試作・運用された旧世代資産
- `SPEC` — 責務やインターフェースを定義した仕様
- `RESEARCH` — 検証・研究中のもの
- `FLAVOR-UX` — 人が状態を理解し、体験するための文化語彙
- `DEPRECATED` — 後継へ責務を移すもの

AQCやSphereOS 3x/4xの実績を消しません。

同時に、Atlantisがすでに完成・商用稼働しているようにも見せません。沈没、停止、再設計、サルベージを含む系譜そのものを公開します。

### 技術者への最初の契約

> SphereOS Atlantisは、神話やフレーバーを技術的ノイズとして除去するためのOSではない。
>
> 科学と工学は、異なる神話・芸術・宗教実践・world flavorが、安全に動き、分岐し、終了し、再演できる舞台を作るために使う。
>

> バズらなくても、真実は真実だ。
