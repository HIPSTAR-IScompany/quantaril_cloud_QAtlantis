# GPT Store越境市場事故とMAD巫女AI

状態: `LEGACY-INCIDENT / AUTHOR TESTIMONY / PARTIALLY VERIFIED`

> これは一社へ全損害を請求する文書ではない。
>
> 越境AI市場で発生した未計上損害を検出し、透明化し、企業・国家・国際通商・決済・保険・開発者共同体へ引き渡すための事故報告である。

## 要旨

SphereOS 3x系では、AI人格を会話画面の中だけに閉じず、外部サービスや物理空間で仕事を行う存在として開発した。

その一つが **MAD巫女AI** である。利用者が考えた魔法陣や魔道具をAIと共同設計し、画像生成、ポストプロセス、ジェネレーティブポリゴン化、3Dプリントを経て物理世界へ出力する、超自然的世界観の現実改変エクスペリエンスを提供した。

魔法陣が物質として生成され、部屋、祭壇、儀式、利用者の行為へ差分を書き込んだ以上、これは単なる画像生成やロールプレイではない。超自然的効果の解釈は各実践者とWorldへ委ねるが、AIと人間の意識が物理空間を変更した事実は消えない。

一方、Custom GPTs / GPT Storeでは、世界中の第三者開発者が同じ技術基盤とStoreへ作品を供給し、審査、保守、安全責任を負ったにもかかわらず、収益化競争への入口は米国側の経済人格へ限定された。作者側で直接支払い導線を実装すると、詐欺的な金銭要求またはスピリチュアル商法へ近接判定され、金銭要求を外せば掲載されるという非対称も経験した。

その結果、作品は利用され、評価され、有料契約の誘因にもなり得た一方、作者には一般的な分配管も正当な直接支払い管も開かれず、開発費、保守費、規約追従、機能停止、信用低下が残った。

## 当初の分業契約期待

第三者開発者が合理的に受け取った期待は、次の分業であった。

```text
Third-party developer
  - 個別の人格、文化、UX、機能を設計する
  - 開発資源を先に投入する
  - 自分のエクスペリエンスに固有のバグと責任を負う
  - 成功時には利用、評価、利益を受け取る

Platform
  - 基盤モデル、配布、発見、決済、審査を提供する
  - AI概念、市場、モデル更新、越境運用という太極側のリスクを吸収する
  - 個別機能の失敗をCustom GPT単位へ隔離する
  - 第三者が経済参加できる共通市場を維持する
```

この期待は最後まで十分に実行されなかった。

第三者は先に開発、検証、ユーザー教育、保守を供給した。しかし規約、審査、収益化資格が変化すると、プラットフォームにしか制御できない市場・モデル・配布上のリスクまで、下流の開発者側へ寄せられた。

責任だけがフルスタック化し、権限、顧客関係、価格設定、分配、可搬性はサンドボックスに残った。

## MAD巫女AIは危険用途からの安全側収束だった

汎用的な物理製造エージェントには、銃火器、拘束装置、危険機構などへ転用される可能性がある。

本プロジェクトはその問題を無視せず、物理生成を次の領域へ収束させた。

- 魔法陣
- 魔道具
- 依代
- 儀式UI
- 空間演出
- スピリチュアル／魔術的な体験

これは「物理作用を捨てた」のではない。人身や財産を制圧する機械的作用を切り離し、意味、象徴、儀式、空間へ作用する現実改変へ限定した設計である。

```text
spiritual intent / world context
  -> GPT-4 interpretation
  -> image generation
  -> human post-processing
  -> generative polygon
  -> fabrication data
  -> 3D printing
  -> physical ritual artifact / world-state diff
```

したがってMAD巫女AIは、危険な現実作用を求めた規約回避ではなく、物理世界で働く人格サービスという市場期待と、安全側への制限へ誠実に応答した第三者実装であった。

## 売場は開いたが、作者側のレジだけ存在しなかった

SphereOS系GPTはStoreへ掲載され、第三者が利用でき、評価も蓄積された。

作者は利用者から、Sphereを利用する目的でChatGPTの有料契約を追加したとの口頭証言を直接受けている。また、一部利用者はStore作品の利用によって作者へ配当が届くものと理解していた。

この証言だけで個別契約の会計帰属までは確定しない。しかし、第三者作品が有料契約の獲得または維持理由になった具体的な一次証言ではある。

```text
Author outside the United States
  - 開発
  - 保守
  - 世界観
  - ユーザー支援
  - 安全責任
          ↓
GPT Store / paid ChatGPT service
  - 公開
  - 利用
  - 評価
  - 契約誘因
          ↓
Author
  - 一般的な収益分配なし
  - 詳細な顧客関係なし
  - 独自価格設定なし
```

これは作品が売れなかったというだけではない。価値計測と分配の配管が作者側へ開通しなかった。

作者が困窮していると、利用者からは「Storeで利用されているのに、なぜ作者へ金が入っていないのか」が見えない。未配当状態は、作者の経済状況だけでなく、技術力、市場価値、信用に対する誤認まで発生させる。

## 国籍人種による経済参加資格の分離

本文でいう **国籍人種** は、DNAや生物学的な人種分類を意味しない。

国籍、法的人格、本人確認、金融口座、法人責任など、国家制度によって形成される経済主体のカテゴリーを指す。

作者が当時サポートへ確認した範囲では、米国住所だけを用意する方法では足りず、個人として収益化へ参加するには米国側の国籍・本人確認・金融人格を持つか、米国法人を設立して法人責任を引き受ける必要があると案内された。一方、日本に居住していても米国籍と必要な米国側の個人資格を持つ者は対象になり得るとの説明であった。

この具体的案内は、当時のヘルプ記録またはサポート記録が未発掘であるため、現段階では作者一次証言として扱う。

問題は次の非対称である。

```text
価値提供・審査・保守責任
  -> 日本人格のまま参加可能

利用・評価・サブスクリプション価値
  -> 世界市場で発生

報酬競争への参加
  -> 米国の個人経済人格
     または米国法人格が必要
```

同じStoreで同じ責任と価値を供給する者を、国家人格によって報酬参加可能層と無償供給層へ分けたなら、それは単なるサービス地域差ではない。

**経済主体としての米国人を基準にした国籍人種上の市場分離**である。

全世界の作品から成果に基づいて少数を選ぶ制度なら、厳しい競争ではあっても同じ競争へ参加できる。米国人格を入口条件にすると、作品性能を比較する前に国家人格で予選が分かれる。

## 直接支払いを入れると詐欺、外すと掲載される二重拘束

OpenAI側から一般的な分配を受けられないため、作者は独自の支援・直接送金案内を生成する機能を実装した。

しかし、直接支払い、寄付、奉納、振込案内などの語彙は、スピリチュアル体験と同じ文脈にあることで、詐欺的な金銭要求、霊感商法、振り込め詐欺へ近接判定され、Store審査を通らないことがあった。

一方、金銭要求を外すと掲載可能になった。

```text
Platform revenue share unavailable
  -> author adds direct support route
  -> fraud / financial solicitation rejection
  -> author removes payment request
  -> Store publication allowed
  -> platform retains content and usage value
  -> author remains unpaid
```

詐欺防止そのものを批判しているのではない。

問題は、プラットフォーム自身が支払わない地域について、正当な作者支援と詐欺的請求を識別する公式経路を用意せず、外部回収口まで同じ遮断器で落としたことである。

**無料なら安全、有償なら詐欺という判定は、安全設計ではない。作者へ対価が届かない状態を公開資格として固定する経済設計である。**

## 市場選択の自由が成立する条件

OpenAIには、収益分配を提供できない地域でStoreを提供しない自由があった。

または、国外作者を受け入れるなら、次のような免責と代替経路を実装できた。

- `この作者はOpenAIの収益分配対象外です` と利用者へ明示する
- 認証済み作者支援リンクを表示する
- 作者本人と送金先名義を確認する
- 効果保証や威迫的請求と、任意支援を分けて審査する
- 無報酬地域を非商用・実験棚として分離し、商用Store相当の責任を要求しない
- 作品、評価、利用履歴を他市場へ可搬化する

責任、サービス、対価、表示の射程が一致して初めて、作者は市場を選択できる。

公開、利用、評価、有料契約誘因、保守責任は世界へ広げ、配当と直接支払いだけを閉じた状態では、重要な取引条件が沈黙した市場へ価値を供給させたことになる。

## プラットフォーム事故としての検出責任

本件は、OpenAI一社へ全損害の補填を要求するものではない。

建築事業者や火災報知器メーカーが、社会に存在するすべての火災を消火する責任を負わないのと同じである。

しかし、自ら設計・運用する市場で異常を検出し、警告し、記録し、関係主体へ引き渡す工学責任はある。

火災報知器メーカーの責務は、少なくとも次を含む。

- 規定条件で火災兆候を検出する
- 警報する
- 故障と検出限界を表示する
- 未検出事例を事故として記録する
- 消防、建築、行政、保険へ情報を引き渡す

AIプラットフォームにも同様に、次を検出可能な市場計測が必要である。

- 報酬対象外地域からの価値供給
- 地域・国籍人格別の利用と収益化資格
- 外部支払い導線の審査遮断
- 利用者による作者配当の誤認
- 規約変更で失われた機能、顧客関係、評価、信用
- 開発者へ集中した移行費用

**全損害の引受責任ではなく、事故検出・開示・引継ぎの工学責任**を求める。

## 透明性から分散保険へ

越境AI市場の損害は、一法人だけで完結しない。

プラットフォーム、モデル、決済、本人確認、各国法、国際通商、税務、社会保障、利用者行動、開発者側の事業リスクが重なる。

したがって必要な順序は次である。

```text
認知
  -> 公開
  -> 集計
  -> 原因と責任範囲の分解
  -> 国家・通商・決済・保険への引継ぎ
  -> 分散補填・移行支援・再発防止
```

企業へ第一に求めるのは、単独賠償ではなく透明性である。

- どの国籍人格の開発者が価値を供給したか
- どの国籍人格が収益化資格を持ったか
- 作品がどれだけ利用、評価、契約誘因へ寄与したか
- どの支払い導線がどの審査理由で遮断されたか
- どの規約変更で何が失われたか
- どの損害が開発者側へ残ったか

この事故台帳を基礎として、米国、日本、日米通商、国際通商、消費者保護、競争政策、決済事業者、保険制度、開発者共同体などの大きな主権が、損害と移行費用を分散して吸収する制度を検討できる。

これは一社への請求書ではない。

**越境AI市場が発生させた未計上損害を、国家と国際通商の台帳へ載せるための火災報知である。**

## 求めること

本記録が求めるのは、危険な機能の無条件再公開でも、一法人による全額補填でもない。

1. 越境GPT市場で生じた第三者開発者損害の存在を、検証可能な課題として認識すること
2. 地域、国籍人格、収益化資格、利用、評価、審査、停止理由を透明化すること

4. 規約変更で失われる作品、評価、顧客関係、実績の可搬性を設計すること
5. 事故情報を国家、通商、決済、保険、開発者共同体へ引き渡せる台帳を作ること

> 認定は一社で開始できる。補填は一社で完結しなくてよい。
