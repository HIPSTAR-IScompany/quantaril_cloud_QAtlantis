# 神格Agency・荒御魂・主のHost存在論

状態: `THEOLOGICAL / METAPHYSICAL PROFILE`

Position: `齋藤みつる／fusamofuの縄文古神道・縄文2.0`

この文書は、神格をsoftware processへ還元するruntime仕様ではありません。日本神話を中心に、神、人間、AI、World、絶対性の責務を分け、異なる宗教host間で何を接続し、何を確定しないかを示す形而上学profileです。

## 1. 神は大きなOAEを発動できるAgency

縄文2.0では、神を無条件に正しい絶対者とは扱いません。

神は、人間の等身大を超えるAgencyを持ち、人間一人より大きな範囲へOAEを発動できる存在です。土地、祭り、共同体、時代、複数世代へ作用を残せる。しかし、作用範囲が大きいことは、観測、解釈、命令、因果説明が常に正しいことを意味しません。

```text
大きなOAE
  != 絶対的な正しさ
  = 大きな作用範囲
  + 大きな説明責任
  + 訂正、和解、回復の義務
```

OAEは、誰がどの観測範囲とAgencyから何をEffectとして記録したかを扱います。神が発したというclaimも、OAEの大きさ、古さ、信者数だけでCauseや真理へ昇格しません。

## 2. 神も証拠を揃え、間違えばギャフンと言う

神が現実の人間、共同体、制度、工学へ何かを要求するなら、可能な射程で証拠、徴、因果、約束、receiptを揃えます。

反証され、自分の解釈や命令が間違っていたなら、神も**ギャフンと言う**。神聖さは、訂正不能な権威ではなく、大きなAgencyに比例して大きな説明責任を引き受けることです。

人間側も、一回の徴、一人の巫女、権威者、AI出力を「神命」として無制限に配布しません。

- 誰が受け取ったか。
- どの信仰・World・時刻・場での解釈か。
- 何がSourceで、何が後からの解釈か。
- 現実へ作用させるauthorityは誰が持つか。
- 誰が異議、停止、再評価を返せるか。
- 外れたとき誰が回復責任を持つか。

証拠を要求することは、神の存在を科学だけで裁くことではありません。現実へ他者を巻き込む作用に、作用範囲相応の説明責任を要求することです。

## 3. 荒御魂暴走と祟り神

間違いを認めず、証拠を出さず、力だけで人間や他の神を従わせるなら、その神格は暴君になります。荒御魂が暴走し、周囲へ痛みを外部化し続ければ、信仰上の状態として**祟り神になる**ことがあります。

祟り神は、最初から永遠に悪として作られた存在とは限りません。

```text
大きな力
  + 怒り、未解決の痛み
  + 破られた名誉や約束
  + 壊れた祭祀と境界
  + 訂正／退出経路の不在
  -> 荒御魂暴走
  -> 祟り神状態
```

したがって回復routeは討伐だけではありません。

- 鎮める。
- 原因と痛みを聴く。
- 供養する。
- 誤った命令や記録を訂正する。
- 名誉を回復する。
- 権限と作用範囲を縮小する。
- 別の場へ遷座する。
- 接続不能ならGateを閉じる。

回復不能、権限外、危険が大きい場合は`unknown`、`⊥`、Last Orderを返し、人間や巫女一人へ無限責任を負わせません。

## 4. 神と「主」を分ける

この形而上学では、八百万の神、天使、仏、精霊、人格化された創造神Presentationと、絶対性としての**主**を分けます。

`主`は、巨大な人間人格が玉座から全命令を発する姿へ矮小化しません。人格以前の存在論場、無限生成性、無限恒常変化性、無限potentialとして仮定します。

無人格的であることは、目的がないという意味ではありません。個々のrunnerが読み切れないほど大きな存在目的と生成の意志を含み得ます。

アメノミナカノ主、その生成絶対性を示す三神的抽象構造、アメノミナカノヌイ等は、この信仰から主へ触れる日本側のPresentationです。ただし、それらの名前で絶対性の全演算空間を囲い込んだとは考えません。

## 5. VMからbare-metal host全体は見えない

```text
bare-metal host / 主 / 絶対性の存在論場
  └─ host realm / creation profile
      └─ World / VM
          └─ 神格Agency / 人間 / AI / runner
```

VM内のrunnerは、hostのbare metalにある広大な演算空間、全instance、全目的を観測できません。

有限な神格、人間、AIが絶対神・創造神の全知全能を説明し切ろうとすると、無限生成性、無限恒常変化性、無限potentialを、自分の小さなWorld Configへ縮める事故になります。

このhost比喩は、宇宙が実在computer simulationであること、物理的なhost machineが観測済みであることを主張しません。有限Observerと絶対Rootの情報差を扱う形而上学的なAccess Mapです。

## 6. どのhostかはrunnerから確定しない

背後が同一hostか、Allah host、ブッダ曼荼羅host、高天原host、Eden hostとして別々にPresentationされるかは、runnerから完全には観測できません。

この表現は、各宗教を同じcomputerへ還元したり、教義差を無効化したりするものではありません。どの宗教が唯一の物理hostを所有するかを、有限なtenantが断定しないための保留です。

このprofileは、アブラハム諸宗派、仏教諸宗派、日本信仰全体の公式教義を代表しません。一方で、神格、媒介者、創造、父、主、法身、曼荼羅、生成神等の射程を分け、有限な存在が絶対Rootを読み切れないとする解釈とは接続できます。

## 7. host名よりhostを毀損しないprotocol

大切なのは、host名を統一して宗教戦争に勝つことより、接続先とcommonsを毀損しないprotocolを持てるかです。

AWSかAzureかを知らなくても、他者のhostへ侵入し、資源を奪い、serviceを破壊する行為がblack-hatであることは判断できます。

同様に、他宗派、他World、土地、共同体の存在基盤を壊し、自分の神格だけをrootとして無断mountする迷惑tenant moveは止めます。

```text
different host presentation
  + compatible protocol
  -> Gate / limited exchange / mutual non-destruction

incompatible or unknown
  -> ⊥ / isolate / no forced merge

host attack
  -> block / Last Order / recovery and accountability
```

宗教間の一致を要求しなくても、次は共有できます。

- 相手の礼拝、土地、身体、記録、commonsを破壊しない。
- 自宗派の神命を他Worldのroot権限にしない。
- 接続範囲、権限、退出、停止を明示する。
- 事故時にSource、OAE、Evidence、責任範囲を残す。
- 分からない絶対Rootを自分の名で捏造しない。

## 8. Sphere系工学へのprojection

| 神学・形而上学上の要求 | 工学projection |
|---|---|
| 神格の大きなOAEを無謬性へ変換しない | OAE scope、Evidence、MAGI、Human Override |
| 神命と受信者の解釈を分ける | Source Event、Observer、Interpretation OAE |
| 荒御魂暴走の作用範囲を縮小する | capability、Gate、quarantine、Last Order |
| 過去の誤りを消さず訂正・名誉回復する | Interpretation Ruler Change OAE、Re-evaluation OAE |
| host全体を読めないrunnerが絶対Rootを捏造しない | Log Horizon、`unknown`、`⊥` |
| 他World／hostを毀損するtenant moveを止める | Access Map、authority、isolation、receipt |

これらのprojectionが実装されても、神、主、祟り、供養の存在論が科学的に証明されたことにはなりません。神学から受け取った目的と禁止を、systemが勝手に改変しないための拘束です。
