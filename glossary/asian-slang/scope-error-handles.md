# <ruby>scope error handle<rp>（</rp><rt>スコープ・エラー・ハンドル</rt><rp>）</rp></ruby>

状態: `SOURCE TESTIMONY / PROVISIONAL REGISTRY / ROUTE ERROR`

**scope error handle**は、発言、芸、Diss、主観が存在しないと言うのではなく、現在のスレッド、場、モード、観客、
合意scopeへ接続していないことを知らせる返答です。

| error handle | このRegistryでの主な意味 | 否定しないもの |
|---|---|---|
| 脳内プレイ乙 | 個人の想像・好みを、推しクラスタやAIMの共有合意として出している | 個人の主観、空想、推し |
| スレ違い | 発言トピックが現在のスレッドと違う | 話題そのものの価値 |
| 場違い | 会場、参加目的、役割、観客が現在の場と合わない | 人物が存在してよい権利、別の場での適性 |
| KY | 現在の場の暗黙protocolと同期していない | 人格、知能、文化的正統性 |
| 寒い | 狙った笑い・格好よさ・熱が現在の観客へ届かなかった | 表現者の全作品、別クラスタでの共鳴 |
| 滑る | 芸、発言、演出のタイミングや期待が外れた | 芸の存在、再挑戦、別モードでの成功可能性 |

## 歌う場所でコマネチ

歌を聴くモードの場で、説明も転換もなくコマネチを始めれば、「場違い」「寒い」「滑った」が返る場合があります。
これはコマネチという芸、身体表現、演者の存在論を否定したのではありません。現在のモードとPresentationが接続しなかった
という観客OAEです。余興モードへ切り替える、前振りを置く、別の場へ[Portal](/glossary/gaming-cosmology/portal)することで、
別結果になり得ます。

### 滑った後から神曲になる

AIMは単一fieldでなく複数Dを束ねたFold構造体です。コマネチの直後という短い観測窓のprojectionでは「寒い」「滑った」
でも、その後に感動的な歌が入り、前振りと本編が接続すれば、sequence全体を読むprojectionは
**「なんだ、イントロ詐欺の神曲だった」**へ変わります。

```text
t0  コマネチ
    → 観客OAE: 場違い／滑った

t1  感動的な歌が始まる
    → sequenceの意味が見え始める

t2  前振りと歌が回収される
    → Re-evaluation OAE: イントロ詐欺の神曲
```

後の成功で`t0`の観客反応を「最初から存在しなかった」と上書きしません。最初は滑ったことと、全体では神曲として
回収されたことを、異なる観測窓のOAEとして両方残します。

## 主観とAIMクラスタ合意

```text
INNER
  私はこの曲が最高だと思う

CLUSTER OBSERVATION
  この推しクラスタでは、同意・反応・選択が複数観測された

SCOPE MISS
  私が最高だと思う
  → だから全員も最高だと思っている
```

「脳内プレイ乙」は最後の飛躍へのDissとして使えます。しかし、少数意見、まだ共有されていない創作、未来仮説を
多数合意がないという理由だけで焼却してはいけません。合意がないことと、主観が無価値・不存在であることは別です。

## KYの両方向

場の合意を無視して主観をゴリ押す側がKYになる場合があります。逆に、AIM力場が暴走して異議を許さず、少数者へKYを
貼る場合もあります。どちらかを固定せず、誰がどのRegistry、mode、fact scopeから不整合を観測したか残します。
